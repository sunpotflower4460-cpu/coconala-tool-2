# 00 — 商品仕様書

## 1. 商品の目的

問い合わせ内容を価格表と照らし合わせ、見積書を作るまでの転記・検索・計算を減らす。

本商品は「販売者による設定代行」ではなく、購入者自身が初回設定して使用する完成ツールである。

---

## 2. 商品の約束

### 約束すること

- 初回案内に沿って、自分で使い始められる
- AIを契約しなくても基本的な帳票作成ができる
- 問い合わせ文をAIで整理できる
- 金額を自分で確認してから発行できる
- データをローカル保存できる
- バックアップと復元ができる

### 約束しないこと

- 見積内容が事業上正しいこと
- 税務・法務上の完全適合
- AI読み取りの100%精度
- すべての会計ソフトとの連携
- すべてのCSV形式の自動判定
- 購入者固有の業務への無料対応

---

## 3. 標準ユーザーストーリー

### US-01 初回設定

利用者として、質問に答えるだけで屋号、住所、振込先、ロゴを設定したい。説明書を読まずに最初の見積書まで到達したいからである。

### US-02 価格表登録

利用者として、商品を1件ずつ登録するか、見本CSVを使って一括登録したい。既存の価格表を活用したいからである。

### US-03 手動見積

利用者として、AIを使わずに顧客と明細を選び、見積書を作りたい。AIサービスの契約や通信障害に依存したくないからである。

### US-04 AI整理

利用者として、問い合わせ文を貼り付けて、商品候補・数量・納期・不明点を整理したい。読み直しと転記を減らしたいからである。

### US-05 確認

利用者として、AIが確信を持てない項目を黄・赤で確認したい。誤った金額をそのまま発行したくないからである。

### US-06 帳票変換

利用者として、承認済み見積から請求書や納品書を作りたい。同じ明細を再入力したくないからである。

### US-07 履歴保全

利用者として、過去に発行した書類を当時の内容のまま見たい。現在の価格表や住所変更で過去書類が変わると困るからである。

### US-08 バックアップ

利用者として、全データを1つのバックアップへ保存・復元したい。PC故障や買い替えに備えたいからである。

### US-09 問い合わせ

利用者として、個人情報を含まない診断ファイルを作りたい。「動かない」だけでなく原因調査に必要な情報を安全に伝えたいからである。

## 5. 状態と色の意味

### AI照合状態

- `matched` / 緑: 価格表の候補がほぼ一意で、数量も明確
- `review` / 黄: 複数候補、推測を含む、または一部不足
- `unresolved` / 赤: 価格表に存在しない、数量・単位が不明、矛盾がある

色だけに依存せず、アイコン・文字ラベルも併記する。

### 書類状態

- 下書き
- 発行済み
- 承認済み
- 却下
- 請求済み
- 入金済み
- 取消

---

## 6. 金額計算ルール

- 金額は円の整数で保持する
- 税抜・税込の設定を明示する
- 税率は明細単位で保持可能にする
- 値引きは明細値引きと全体値引きを分ける
- 端数処理は切り捨て・四捨五入・切り上げから設定する
- 計算順序を仕様として固定し、自動テストする
- 発行後は計算結果をスナップショットとして保存する

---

## 7. AI出力の最低形式

AIへ自由文を返させず、次の意味を持つ構造化データを要求する。

```json
{
  "summary": "依頼の短い要約",
  "requested_due_date": "YYYY-MM-DD or null",
  "items": [
    {
      "source_text": "元の文章部分",
      "normalized_name": "整理した名称",
      "quantity": 3,
      "unit": "本",
      "catalog_candidates": [
        {
          "catalog_item_id": "id",
          "confidence": 0.93,
          "reason": "動画編集という表現が一致"
        }
      ],
      "status": "matched | review | unresolved",
      "questions": []
    }
  ],
  "global_questions": []
}
```

AIから返ったIDや金額をそのまま信用しない。アプリ側で存在確認・型確認・範囲確認を行う。

---

## 8. 個人情報と通信

- 会社・顧客・帳票データは原則ローカル保存
- AIを使う場合、利用者が実行ボタンを押した文章だけを送信
- 送信前に、送信される内容を表示できる設計にする
- APIキーを平文DBやログへ保存しない
- 診断ファイルから顧客名、住所、メール、本文、APIキーを除外する
- 遠隔計測は初期版では原則オフ。導入時は明示同意を得る

## 9. 販売プランの境界

### Standard想定

- 1屋号
- ローカル保存
- 主要4帳票
- CSV価格表
- AI読み取り
- バックアップ
- 1年間の機能更新

### Pro想定

- 複数屋号
- 複数帳票デザイン
- 詳細な原価・利益表示
- 会計ソフト向けCSVプリセット
- 優先サポート

プラン差はコード内のFeature Flagで管理し、画面を複製しない。

---

## 10. サポート境界

### 不具合として対応するもの

- 正しい手順でアプリが起動・保存・出力できない
- 計算仕様どおりに金額が出ない
- 対応OSで再現するクラッシュ
- マニュアル記載機能の故障

### 個別対応・追加商品とするもの

- 価格表の代理作成
- 購入者の会社情報入力
- 見積内容の妥当性判断
- 税務・法務相談
- 独自帳票や外部サービス連携
- PC全般の操作支援

---

## 11. 商品としての非機能要件

- 起動からホーム表示まで通常3秒程度を目標
- 主要操作はキーボードのみでも可能
- 文字サイズを小さくしすぎない
- 日本語入力中にショートカットを誤作動させない
- クラッシュ時に未保存下書きを可能な範囲で復旧
- 1000顧客、5000価格項目、10000書類を想定して検索確認
- バックアップ形式に`schema_version`を持たせる
- DB移行は一方向だけでなく、失敗時のロールバック方針を持つ
