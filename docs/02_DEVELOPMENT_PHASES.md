# 02 — 開発段階指示書

## 全体方針

- コードで自動化できる作業を先に進める
- 証明書取得、署名、販売ページ登録など、人間が必要な作業は最後にまとめる
- 各Phaseは「動く縦の一本」を完成させてから次へ進む
- UIだけ、DBだけを大量に作り、最後につなぐ進め方は禁止
- 各Phase終了時にテスト・操作手順・残課題を更新する

---

# Phase 2 — 発行・帳票・変換

## 目的

見積書を実際に業務で渡せる形にする。

## 実装

- 見積書の発行
- 会社・顧客・明細・計算のスナップショット保存
- 印刷専用プレビュー
- A4縦レイアウト
- 2ページ以上の改ページ
- PDF保存方式の技術検証
- 書類番号の重複防止
- 見積書→請求書
- 見積書→納品書
- 請求書→領収書
- 書類複製
- 状態履歴

## 帳票で確認する日本語ケース

- 長い会社名
- 長い住所
- 長い商品名
- 20明細以上
- ロゴあり／なし
- 税率混在
- 備考が複数行
- 2ページ目

## 完了条件

- 発行済み書類が後から価格表変更の影響を受けない
- macOS・Windowsで日本語帳票を保存できる
- 見積から変換した書類に元書類IDが残る
- 2ページ帳票の合計欄が崩れない
- 主要帳票の期待値テストがある

# Phase 3 — 問い合わせ文のAI整理

## 目的

この商品の差別化となる「問い合わせ文→見積候補」を安全に実装する。

## 実装

### Provider境界

- `AiProvider` interface
- AIなしProvider
- 最初の実Provider 1つ
- 接続テスト
- タイムアウト
- キャンセル
- 再試行

### 秘密情報

- APIキーの安全保存
- ログ・診断・DBから除外
- 削除ボタン
- 接続確認時にキー全文を表示しない

### 抽出

- 構造化JSON schema
- 問い合わせ要約
- 品目・数量・単位・納期
- カタログ候補
- 信頼度
- 不明点

### 確認UI

- 緑・黄・赤
- 元文章との対応箇所
- 候補切り替え
- 手動項目追加
- AI結果を破棄して手動作成

## 安全規則

- AIが金額を新規発明しない
- 金額は登録価格表からのみ候補化
- AIのカタログIDをDBで再確認
- AI結果は利用者承認まで下書きへ反映しない
- 同じ処理の二重実行で書類を重複作成しない

## テスト

- 明確な問い合わせ
- 数量がない問い合わせ
- 複数候補
- 価格表にない依頼
- 矛盾した納期
- JSON破損
- タイムアウト
- APIキー不正
- 日本語と英数字混在

## 完了条件

- AI失敗後も手動見積へ移行できる
- 不明項目が赤で残る
- AIによる金額確定が存在しない
- 不正JSONが保存されない
- APIキーがログ・診断・通常DBに存在しない

## ユーザビリティ試験

初心者5人へ、説明せず次を依頼する。

1. 初回設定
2. 商品3件登録
3. 顧客登録
4. 問い合わせから見積作成
5. PDF保存
6. バックアップ作成

観察者は手助けせず、迷った場所、誤操作、理解できない言葉を記録する。

## 完了条件

- 5人中4人以上が主要操作を完了
- 価格表の代理入力を前提としない
- 診断ファイルに禁止情報が含まれない
- バックアップ破損時に元データを失わない
- FAQで基本問い合わせの大部分を自己解決できる

# Phase 5 — 販売品質・配布・更新

## 目的

「開発者のPCでは動く」から「購入者へ安全に渡せる」へ進める。

## コードで先に行うこと

- アプリID・バージョン管理
- Feature Flag
- ライセンス境界の抽象化
- 更新確認UI
- 署名付きアップデート設定
- リリースワークフロー
- CHANGELOG生成
- インストーラー名・ファイル名
- バージョン情報画面
- クリーンインストールE2E
- アップグレードE2E

## 人間が最後に行うこと

`docs/MANUAL_STEPS.md`へ集約する。

- Apple Developerの証明書確認
- macOSコード署名・公証用秘密情報
- Windowsコード署名証明書
- 販売者情報
- ダウンロード提供先
- 更新ファイル配置先
- ココナラ商品登録
- 利用規約・特商法表示の最終確認

## ライセンス方針

初期販売は複雑な常時オンライン認証を避ける。

優先順位:

1. 販売テスト中はライセンスなし、または簡易な署名済みライセンスファイル
2. 売上と不正利用リスクが確認できてから正式ライセンスサーバーを検討
3. ライセンス障害で帳票データが開けなくなる設計は禁止

## 完了条件

- macOS署名・公証済みインストーラー
- Windows署名済みインストーラー
- 更新ファイルの署名検証
- 更新失敗時に旧版が起動可能
- クリーンPCでインストール確認
- アンインストール時にデータ扱いを選べる
- リリース手順が再現可能

# Phase 6 — ベータ販売と正式販売

## 目的

少人数の実利用で、商品説明と実物の差をなくす。

## ベータ人数

5〜10人。

## 観測項目

- 初回設定の完了率
- 最初の見積作成までの時間
- CSV失敗率
- AI候補の修正率
- PDF保存成功率
- サポート問い合わせ内容
- 「期待していたができなかったこと」

## リリース判断

重大な計算誤り、データ消失、復元不能、秘密情報漏えい、発行済み書類の変化が1件でもあれば正式販売しない。

小さな見た目の問題は優先度を付け、販売後更新でもよい。

## 正式販売時の同梱物

- macOS版
- Windows版
- 初回設定ガイド
- 5分操作動画
- PDFマニュアル
- CSV見本
- FAQ
- 利用規約
- 免責事項
- バージョン・更新案内
- 問い合わせ方法
