# 0002 — ローカルファーストとSQLiteによるデータ保存

## ステータス

採用

## コンテキスト

会社情報・顧客情報・価格表・発行済み帳票は、購入者の端末内に保存することを商品の約束としている(`docs/00_PRODUCT_SPEC.md` 8章)。クラウドDBを前提にすると、月額サーバー費用や個人情報の預かりリスクが発生し、買い切り販売のモデルと相性が悪い。

## 決定

公式の `tauri-plugin-sql`(SQLite)をアプリ内DBとして採用し、DBファイルは各端末のアプリデータディレクトリに保存する。

- 接続ごとに `PRAGMA foreign_keys = ON` を有効化し、孤立データを防ぐ。
- スキーマ変更は`src-tauri/migrations/`配下の番号付きSQLファイルのみで行い、アプリ起動時に未適用分を順に適用する。
- `application/ports/database.ts` にDB操作の抽象を置き、`infrastructure/database/` が実装する。domain層はSQLに依存しない。

## 影響

- 複数端末間のリアルタイム共有はできない(バックアップファイルによる手動移行で対応)。
- マイグレーション失敗時の保護(バックアップ・ロールバック)を別途実装する必要がある。
- テストではNode上で実SQLiteエンジンを使い、migrationとリポジトリのSQLを検証する。
