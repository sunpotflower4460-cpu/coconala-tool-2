# 0004 — 発行済み書類はスナップショットとして保存する

## ステータス

採用

## コンテキスト

価格表の単価や会社情報(振込先・住所等)は将来変更されうる。しかし過去に発行した見積書・請求書・納品書・領収書の内容が、後からの変更によって書き換わることは許されない(`docs/00_PRODUCT_SPEC.md` US-07、販売停止条件「発行済み書類が後から変化」)。

## 決定

`documents`テーブルに以下のスナップショット列を持たせ、発行時点の状態をJSONとして固定する。

- `company_snapshot_json`: 発行時点の会社情報
- `client_snapshot_json`: 発行時点の顧客情報
- `calculation_snapshot_json`: 発行時点の計算結果(端数処理方式・税率内訳を含む)

`document_lines`にも、商品マスターIDだけでなく発行時点の商品名・単価・税区分を保存し、価格表側の変更から独立させる。

下書き状態(`draft`)の間はスナップショットを持たず、価格表・顧客マスターの現在値を参照して都度計算する。発行(`issued`)以降の状態遷移でスナップショットを固定し、以後は再計算しない。

## 影響

- 発行後の書類編集は「複製して新規下書きを作る」操作に限定する(直接編集不可)。
- スナップショットの分だけDB容量は増えるが、金額の正確性を優先する。
- 発行操作の実装(Phase 2)では、スナップショット生成のタイミングと状態遷移の整合性を単体テストで保証する。
