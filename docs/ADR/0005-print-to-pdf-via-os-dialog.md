# 0005 — 帳票のPDF化は初期実装としてOS標準の印刷ダイアログを使う

## ステータス

採用(Phase 2初期実装。Phase 4/5で強化予定)

## コンテキスト

`docs/01_REPOSITORY_STRUCTURE.md` 7章は、帳票PDF化の初期実装として「Reactで印刷専用HTMLテンプレートを描画→画面プレビュー→OSの印刷ダイアログから印刷・PDF保存」を推奨し、ワンクリックPDF出力は販売前の強化事項としている。

技術的選択肢として以下を検討した。

1. OS標準印刷ダイアログ経由(`window.print()` + `@media print` CSS)
2. Rust側でHTML→PDFへ変換するライブラリ(例: `wkhtmltopdf`、`headless_chrome`連携)を組み込み、ワンクリック出力する
3. PDF生成ライブラリ(例: `pdf-lib`、`jsPDF`)をフロントエンドで使い、レイアウトをコードで組み立てる

## 決定

Phase 2では選択肢1を採用する。

理由:

- 追加の外部バイナリ・重量級依存を増やさずに実装できる(「不要な大型フレームワークを増やさない」という方針に合致)。
- macOS・WindowsどちらのOS標準印刷ダイアログも「PDFとして保存」を標準搭載しており、追加実装なしでPDF保存要件を満たせる。
- 印刷専用HTMLテンプレートはそのまま将来のワンクリックPDF出力(選択肢2)へ移行しやすい(同じテンプレートをRust側のヘッドレスレンダラーに渡す設計にできる)。

`src/features/document-preview/DocumentPrintPage.tsx`に印刷専用ルートを用意し、`@media print`でA4縦・余白・改ページ制御を行う。ナビゲーション等の画面要素は印刷時に非表示にする。

## 影響

- 利用者は「印刷」ボタン→OSダイアログ→「PDFとして保存」を選ぶ、という1手順増える(ワンクリックではない)。
- 明細が多いページの改ページ位置はブラウザの印刷エンジンに依存する。`thead`の`display: table-header-group`により2ページ目以降にもヘッダー行を再掲し、`tr`に`break-inside: avoid`を指定して行の途中改行を防ぐ。
- Phase 4/5で「ワンクリックPDF出力」を評価する際、選択肢2(Rust側レンダリング)を再検討する。その際もこのADRを更新する。
