# 0009 — オフラインのライセンスキー(未認証でもデータはロックしない)

## ステータス

採用(Phase 7)。ADR 0008 の「ライセンス障害で帳票データが開けなくなる設計は禁止」を引き継ぐ。

## コンテキスト

ココナラでインストーラーをファイルとして納品するため、インストーラーの転売・共有をある程度抑止したい。
一方で、次の制約がある。

- ライセンスサーバーを持たない(運用費・障害点・個人情報を増やさない)
- インターネット接続なしで使えること(ローカルファースト)
- ライセンスの不具合で、購入者の帳票データが開けなくなってはいけない
- ココナラの規約上、外部の連絡先やアカウントを購入者に作らせない

## 決定

- 販売者が Ed25519 の秘密鍵で署名した **ライセンスキー** を、購入者ごとにココナラのトークルームで渡す。
  - 形式: `MDK1.<base64url(payload)>.<base64url(署名)>`
  - payload: `{ v: 1, prod: "mitsumori-desk", lid: "<ライセンス番号>", iat: "<発行日>" }`
  - 個人情報は入れない。番号と購入者の対応は、販売者の手元の台帳(リポジトリ外)で管理する。
- 署名の検証は Rust(`src-tauri/src/commands/license.rs`、`ed25519-dalek` の `verify_strict`)。
  公開鍵は `src-tauri/license/public_key.b64` に埋め込む。
- キーは `app_settings.license_key` に保存する(秘密情報ではない。バックアップにも含まれる)。
- **未認証(未登録・不正・検証不能)のときにできること**: 閲覧・編集・発行・変換・バックアップ・復元・CSV・AI、すべて。
- **未認証のときの違い**は表示だけ:
  - 画面上部の控えめな案内帯
  - 印刷・PDFに「未認証版」の薄い透かしとフッター文
- 透かしは印刷時に決める。発行済みスナップショットには含めないので、登録後に再印刷すれば消える。
- 書類・マスターの commands/queries と domain はライセンスを参照しない(SEC-04 のテストで検査)。
- 販売者用スクリプト: `pnpm license:keygen`(秘密鍵はリポジトリ外にだけ作る)、`pnpm license:issue`。
- リポジトリには、種を公開している **開発用の鍵** を置く。`pnpm check:release -- --strict` は開発用の鍵のままだと失敗する。

## 影響・限界

- オフライン方式なので、同じキーの共有や、キーの失効はできない。規約(利用台数)と台帳で抑止する。
- アプリを改変すれば透かしは外せる。これは「強い保護」ではなく「正規購入の目印」と割り切る。
- 秘密鍵を失くすと新しいキーを発行できない。販売者は秘密鍵を必ずバックアップする(`docs/MANUAL_STEPS.md`)。
- 古いバックアップ(キー登録前)を復元すると未登録に戻る。その場合はキーを再入力する(ヘルプに記載)。
