# 販売者の作業手順(ココナラでの受注〜納品〜更新)

このファイルは販売者(あなた)向けです。購入者には渡しません。
ココナラの規約(外部の連絡先の交換禁止、クラウドストレージでの受け渡し禁止、トークルームの添付は1ファイル200MBまで)を守る前提の手順です。規約は変わることがあるので、ときどき最新版を確認してください。

## 0. 最初に1回だけ

1. ライセンスの署名鍵を作る: `pnpm license:keygen`
   - 秘密鍵は `~/.mitsumori-desk-license/private.pem` に作られます(リポジトリの外)
   - 表示された公開鍵で `src-tauri/license/public_key.b64` を置き換え、コミットします
   - **秘密鍵を USB メモリなど別の場所にもバックアップ**します。失くすと、新しいキーを発行できません(新しい鍵にするとアプリも作り直しになります)
2. GitHub の Actions で「Installers (ココナラ納品物)」を実行し、Artifacts の `coconala-delivery` から次の2つを取得します
   - `MitsumoriDesk_<版>_mac.zip`(`-unsigned` が付いていたら署名されていないので販売に使わない)
   - `MitsumoriDesk_<版>_windows.zip`
3. 2つの zip を実機で展開・インストールして動くことを確認します(`docs/HUMAN_RELEASE_CHECKLIST.md`)

## 1. 注文が入ったら

1. トークルームで、使うOS(Mac / Windows / 両方)を確認します
2. ライセンスキーを発行します(番号は通し番号にすると管理しやすい)

   ```bash
   pnpm license:issue --id L-2026-0001
   ```

   - 手元の台帳 `~/.mitsumori-desk-license/ledger.csv` に番号が追記されます。memo 欄にココナラの取引番号を手で書いておきます(台帳はリポジトリに入れない)

3. トークルームで「正式な納品」として、zip とキーを送ります(下の定型文)

### 納品メッセージの定型文

```
ご購入ありがとうございます。「見積・請求書デスク」をお届けします。

■ 添付ファイル
・MitsumoriDesk_<版>_<mac または windows>.zip
  (インストーラー・説明書PDF・サンプルCSVが入っています)

■ ライセンスキー(1ご購入につき1つです。他の方へは渡さないでください)
MDK1.xxxxxxxx.xxxxxxxx

■ はじめ方
1. zip を展開し「はじめにお読みください.pdf」の手順でインストールしてください
2. アプリの初回設定が終わったら、左のメニュー「バージョン情報」でライセンスキーを貼り付けて「登録する」を押してください

ご不明な点は、このトークルーム(取引完了後はココナラのメッセージ)でお気軽にお問い合わせください。
```

## 2. 更新版を配るとき

1. 修正を `main` へ入れ、バージョンを上げて(`docs/RELEASE_PROCESS.md`)、Installers ワークフローで新しい zip を作ります
2. 実機で「上書きインストールしてもデータが残る」ことを確認します
3. 購入者へ、ココナラのダイレクトメッセージで zip を送ります(ライセンスキーはそのまま使えるので再送不要)
   - 定型文: 「更新版(<版>)をお届けします。更新の前に『データ管理』でバックアップを作成してから、添付のインストーラーで上書きしてください。」

## 3. ライセンスキーの再送・紛失

- 台帳で番号を確認し、同じ番号で `pnpm license:issue --id <番号> --date <元の発行日>` を実行すると、同じ内容のキーを作り直せます(署名は毎回同じになります)
- 別人へのキーの転送・公開が疑われる場合も、オフライン方式のためキーを無効化することはできません。規約違反としてココナラのルールに沿って対応します
